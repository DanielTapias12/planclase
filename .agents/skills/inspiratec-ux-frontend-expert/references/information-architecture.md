# UX and information architecture

## Start with user tasks
Ask: Who is using the screen and with what permissions? What is the primary task? What must be visible immediately? What is the next action? What is secondary, optional, advanced, or destructive? What happens with absent, delayed, invalid, or long data?

## Hierarchy
Prioritize page purpose, primary action, main content/current step, secondary actions/metadata, then helper information. Use placement, typography, spacing, and contrast before decoration.

## Choose patterns intentionally
- Form for structured input/editing.
- Group related fields by the user's mental model.
- Progressive disclosure for advanced options.
- Table for comparing records; list for readable summaries and independent actions.
- Tabs for closely related sibling views.
- Accordions for secondary content, not essential actions.
- Dialogs for bounded tasks; avoid cramped long workflows.
- Cards only when items are meaningfully distinct.

## Preserve content
Do not invent content or remove real fields to improve a screenshot. Preserve dependencies, validations, data meaning, and actions. Labels describe expected values. Helper text clarifies decisions. Errors explain what happened and how to recover.

## Forms
Order context and required fields first, configuration next, advanced/optional fields after, then review and primary action. Keep labels visible, required status clear, and helper/error text close to the correct control.
